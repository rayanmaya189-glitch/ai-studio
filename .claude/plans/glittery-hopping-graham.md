# Production-Hardening Plan — AI Development Studio

## Context

ADS is a working scaffold: scanner, RAG, code graph, the 5-stage agent pipeline,
both memory systems, chat, tasks, and the service dashboard all run end-to-end
(42/42 backend tests pass). The user wants it brought to **production grade** and
feels "many things are still pending." Investigation confirms the genuine gaps,
across the four areas the user selected:

- **Core features incomplete (F12/F13):** code editing is a bare textarea (no
  Monaco, no diff viewer); PR generation only produces description text (no real
  git). Documentation & OCR agents are seeded but never run.
- **No production infra:** no app Dockerfiles, no Alembic (schema built via
  `create_all` + hand-maintained `_ADDED_COLUMNS` in `db.py`), no CI, no
  structured logging.
- **No auth/security:** zero `User`/auth concept; every endpoint is open;
  provider API keys are stored **plaintext** in `llm_provider_configs.api_key`.
- **Robustness:** no global error envelope, no rate limiting, ad-hoc error text.

**Overarching constraint (from CLAUDE.md):** the *zero-config invariant* — a
fresh clone must still boot, scan, and browse with no external services and no
keys. Therefore **auth is opt-in** (`AUTH_ENABLED`, default `false`) and all new
infra dependencies must degrade gracefully, never hard-fail.

This is multi-session work. Phases are ordered low-risk → high-risk so value
lands early and the test suite stays green throughout.

---

## Key decisions (defaults chosen — flag in review if you disagree)

1. **Auth is opt-in.** `AUTH_ENABLED=false` by default preserves zero-config and
   keeps existing tests green. When enabled: JWT bearer, bcrypt passwords, roles
   `admin|editor|viewer`, a bootstrap admin from env. Auth tests run with it on.
2. **PR generation = local git** (branch + commit changed files + real `git diff`)
   via the `git` CLI (no new dep), plus the existing LLM description. Pushing /
   opening a GitHub PR is left as an optional follow-up (needs a host token).
3. **Monaco diff** uses `@monaco-editor/react`'s built-in `DiffEditor` — no
   separate diff library needed.
4. **Documentation agent** joins the pipeline as an optional 6th stage. **OCR**
   stays a separate endpoint (it is vision/image work, not a text dev stage).
5. **Structured logging** uses stdlib `logging` + a small JSON formatter (no
   heavy dep), with a request-ID middleware.
6. **Alembic** is added for prod; `create_all` is kept as the zero-config/test
   path (used when no Alembic version table is present).

## Phase 1 — Production infrastructure (foundation, low risk)

**1a. Structured logging + request IDs**
- New `backend/app/logging_config.py`: JSON formatter (stdlib), `configure_logging()`.
- `main.py`: call it on startup; add an ASGI middleware that assigns/propagates an
  `X-Request-ID`, logs method/path/status/duration. Never log secrets.

**1b. Alembic migrations**
- Add `alembic` to `requirements.txt`; create `backend/alembic.ini`,
  `backend/alembic/env.py` (import `Base.metadata` + `engine` from `app.db`,
  `app.models`), and a baseline autogenerated revision matching current models.
- `init_db()` (`db.py`): keep `create_all` for SQLite/zero-config/tests; document
  that Postgres deploys run `alembic upgrade head`. Leave `_ADDED_COLUMNS` as the
  legacy dev path (note it's superseded by Alembic).
- `Makefile`: add `migrate` / `migration` targets.

**1c. Dockerfiles + compose**
- `backend/Dockerfile` (python:3.12-slim, install reqs, non-root, uvicorn),
  `backend/.dockerignore`.
- `frontend/Dockerfile` (multi-stage Node build; set `output: "standalone"` in
  `next.config.mjs`), `frontend/.dockerignore`.
- Extend `docker-compose.yml` with `backend` + `frontend` services behind a
  `--profile app` so the default `up` still only starts backing services.

**1d. CI**
- `.github/workflows/ci.yml`: backend job (ruff check + pytest), frontend job
  (`npm ci` + `next lint` + `next build`).

**Verify:** `pytest` green; `ruff check` clean; `docker compose --profile app build`;
`alembic upgrade head` on a scratch Postgres.

## Phase 2 — Finish core features (F12/F13 + Documentation agent)

**2a. Backend: read a file's contents (needed by Monaco)**
- Add `GET /edit/{project_id}/file?path=` in `app/api/edit.py`, reusing
  `_resolve_under_root` for path-traversal safety; cap file size. Schema +
  `lib/api.ts` client method.

**2b. Frontend: Monaco editor + diff viewer (F12)**
- `npm i @monaco-editor/react`. Rewrite `components/CodeEditPanel.tsx`: file
  picker (reuse `FsBrowser` with `showFiles`), load original via 2a, edit in
  Monaco, toggle a `DiffEditor` (original vs edited), apply via existing
  `api.editApply`. Keep existing state/error conventions.

**2c. Backend: real git-backed PR (F13)**
- New `app/api/pull_requests.py` endpoints (or extend): detect git repo at
  `root_path`; create/switch branch, stage+commit a set of file edits, return the
  real `git diff` and the LLM-generated description. Use `subprocess` + `git`,
  guarded when the project isn't a git repo (clear error, no crash).
- Update `PullRequestPanel.tsx` to drive branch/commit/diff and render the diff
  (Monaco DiffEditor or `<pre>`), keeping the LLM description.

**2d. Documentation agent into the pipeline**
- `agents/graph.py`: add `"documentation"` to `PIPELINE_ROLES` + a role prompt.
  Make included stages optional per-run (so callers can include/exclude it);
  `_build_pipeline_inputs` already seeds memory for all `_DEFAULT_AGENTS`.
- **OCR:** add a minimal `POST /agents/ocr` endpoint that routes an image/document
  to a vision-capable provider; document that it's separate from the dev pipeline.

**Verify:** load/edit/diff/apply a file in the workspace; generate a PR on a git
project and confirm a real branch+commit+diff; run the pipeline and see a
documentation stage; `pytest` for new endpoints.

## Phase 3 — Auth, RBAC & encrypted secrets (highest risk, opt-in)

**3a. Encrypted provider keys (independent of auth, do first)**
- Add `cryptography`; new `app/security/crypto.py` using Fernet keyed by
  `APP_SECRET_KEY` (env). Encrypt `api_key` on write in `api/llm_config.py`,
  decrypt in `providers/registry._build()`. Migrate existing plaintext rows
  on read (treat undecryptable as plaintext, re-encrypt). `/llm-config` still
  returns only `has_api_key` (already does).

**3b. Users + JWT + RBAC (gated by `AUTH_ENABLED`)**
- Add `passlib[bcrypt]`, `python-jose`. New `User` model + Alembic revision.
  `app/security/auth.py`: hashing, JWT issue/verify, `get_current_user` /
  `require_role` dependencies that **no-op when `AUTH_ENABLED=false`**.
- New `app/api/auth.py`: `register`, `login` (token), `me`. Bootstrap an admin
  from `ADMIN_EMAIL`/`ADMIN_PASSWORD` env on startup when auth is on.
- Apply `require_role("editor")` to mutating routes (scan, edit, PR, agent runs,
  memory writes, llm-config); reads allow `viewer`. Wrapped so disabled-auth path
  is unchanged.

**3c. Frontend auth**
- `lib/api.ts`: attach `Authorization: Bearer` from stored token in `http()`;
  add `login/register/me` methods. `app/login/page.tsx`; a lightweight auth
  gate + logout in `app/layout.tsx`. Only active when backend reports auth on
  (extend `/ready` to surface `auth_enabled`).

**3d. Tests**
- `conftest.py`: keep default suite with auth off. Add `tests/test_auth.py` that
  flips `AUTH_ENABLED`, registers/logs in, and asserts 401/403 vs allowed.

**Verify:** suite green with auth off; auth-on tests pass; keys round-trip
encrypted in the DB (inspect raw column — not plaintext).

## Phase 4 — Robustness pass

- Global exception handler in `main.py` → consistent `{error, request_id}`
  envelope; map common exceptions; stop leaking stack traces.
- Lightweight in-process rate-limit middleware on expensive routes (scan,
  agent run, chat), configurable, disabled in tests.
- Tighten Pydantic bounds (path lengths, payload sizes) in `schemas.py`.
- README/CLAUDE.md updates documenting auth, migrations, Docker, and the
  encrypted-secrets requirement.

**Verify:** trigger a handled error and confirm the envelope + request-id; rate
limit returns 429 past threshold; full `pytest` + `ruff` green.
